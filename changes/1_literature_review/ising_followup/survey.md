# Ising follow-up survey: CIM/SB variants, constraint handling, low-rank solvers, and a CPU shortlist

Scope: this fills the gaps listed in `../lit_review_qubo/REPORT.md`. It does not repeat that report's material (Lucas/Glover encodings, unbalanced penalization, Ohzeki HS/dual, bSB/dSB basics, SA/tabu, QBSolv, Kerberos, roof duality, Ohno 2024, Akishima 2025 headline). Metadata below (versions, dates, licenses) was pulled from the PyPI JSON API and GitHub REST API on 2026-09-28, and code-level claims come from reading the source. `[UNVERIFIED]` means we did not confirm it from a primary source. `[inference]` means it is our own reasoning.

Instance shape assumed throughout: n = 10^4–10^6 binaries, m ≈ 144–1000 windows, D sparse n×m with 1–3 nnz per row, one knapsack, min-max objective, surrogate E(x) = Σ_{w∈A} α_w (L_w(x) − τ)^2 + μ Σ s_e x_e. Hardware: 24 CPU cores, 123 GB RAM, no GPU.

## TL;DR

1. **No off-the-shelf SB or CIM code takes a callable or low-rank operator.** Three packages were checked at source level. `simulated-bifurcation` (bqth29) always builds a dense (n+1)×(n+1) tensor, and even its NumberPartitioning model forms `a aᵀ` densely. `cim-optimizer` (McMahon lab) takes dense NumPy only. **MindQuantum's QAIA module is the closest thing to matrix-free.** It accepts `scipy.sparse` J plus an h vector on CPU and implements aSB/bSB/dSB, CAC, CFC, SFC, SimCIM, NMFA and LQA behind one API. Its CPU hot path touches J only through `J.dot(x)` (plus a Frobenius norm that can be bypassed by passing `xi`). Swapping `solver.J` for an object that computes `Dᵀ(α⊙(D·x))` should therefore work with about 10 lines of glue `[inference; untested]`.
2. **Low-rank Ising plus knapsack is published, but only with SA/MCMC on spatial photonic Ising machines (SPIMs).** Yamashita et al. (PRL 2023) map a knapsack to a rank-2 J with a binary slack and a penalty; the demo is n = 13. Yao & Yu (Opt. Lett. 2026) run a 102,400-spin knapsack on a multi-channel SPIM with SA. We found **no publication of SB (or CIM) running matrix-free on a factorized Q with a Lagrangian (dual-updated) budget.** Each ingredient is published separately, so this is novel as a combination and low-novelty as an algorithm (see §7).
3. **The strongest constrained Ising results come from native or Lagrangian constraint handling, and none of them is open source.** Fujitsu's Extended Ising Machine (EIM) is a simulator Fujitsu provided privately. Delacour's self-adaptive Lagrange p-bit machine (DATE 2025) has no code found. Awai et al.'s augmented Lagrangian (arXiv 2606.24241) runs on Fixstars' cloud SA. All three were tested on QKP with n ≤ 300.
4. **Two new gradient/mean-field "annealers" fit our structure better than SB.** FEM (Nat. Comput. Sci. 2025, PyTorch) accepts an arbitrary differentiable expected-objective function. `qqa`/QQA4CO (ICLR 2025, PyTorch, CPU or GPU) reads MPS/LP directly and advertises native "scenario worst-case/CVaR" factors plus augmented-Lagrangian constraints. Either can express the *true* min-max, not just the quadratic surrogate. Both are research code with licence caveats.
5. **We found no evidence that any Ising approach beats LP/MILP on a problem shaped like ours** (linear min-max, few rows, one knapsack, large n). The only "Ising ≥ MILP" results are on dense *quadratic* objectives (QKP, max-cut, dense QUBO) or compare against graph-partitioning heuristics rather than MILP. The one knapsack result (EIM vs Gurobi) compares time-to-known-optimum with Gurobi's time-to-proof (§8).

### `cim-optimizer` (verified)

- **Repo and license.** GitHub [mcmahon-lab/cim-optimizer](https://github.com/mcmahon-lab/cim-optimizer). PyPI **`cim-optimizer`**, latest **1.0.4 (2023-05-31)**; first release 1.0 on 2022-11-03; last push to GitHub 2024-09-12. License **CC-BY-4.0**, which is unusual for code but permissive with attribution. Authors: F. Chen, B. Isakov, T. King, T. Leleu, T. Onodera, P. McMahon (CITATION.cff, 2022-10-25).
- **Algorithms.** Discrete-time measurement-feedback CIM, AHC, CAC and **extAHC**. Dispatch rule in `solve_Ising.py`: CAC is used when h = 0, and AHC/extAHC is used when h ≠ 0.
- **External fields.** Yes. The objective is H = −Σ_{i<j} J_ij σ_i σ_j − Σ h_i σ_i, and a 1,000-spin `SK_ext_h` instance ships with the repo.
- **Input and hardware.** Dense NumPy J and h, converted with `torch.from_numpy(J)`. The step is `MVM = x @ J` with batched replicas. CPU is the default `device`; GPU works via CUDA PyTorch.
- **Dependency pins.** `requirements.txt` pins torch 1.12.1, numpy 1.21.5 and BOHB-HPO 0.5.2 (for tuning), but PyPI `requires_dist` is empty, so pip will not enforce them. Expect friction on Python ≥ 3.11.
- **Max tested size.** Repo instances reach SK/MC N = 1,000, MIRP N = 1,000, and VRPTW rudy files up to about 4,617 spins (from the file names). No larger size is documented.
- **Problem types.** Generic Ising: Max-Cut (Gset G1/G2/G42/G70), SK, Wishart planted, MIRP and VRPTW examples.
- **Fit.** Dense J needs about 4n² bytes, so n = 5×10^4 is about 10 GB and n = 10^5 is about 40 GB. It would run on the full contested set only after pegging. It serves as a reference implementation of CAC/AHC, not a scalable one.

### Head-to-head CAC/AHC vs SB vs SA

- **Zeng, Cui, Liu, Wang, Mosharev, Yung, *Commun. Phys.* 7, 249 (2024)** ([doi:10.1038/s42005-024-01705-7](https://doi.org/10.1038/s42005-024-01705-7)) is the only published head-to-head we found. It compares aSB, bSB, dSB, SimCIM, CAC, CFC, SFC, NMFA and LQA against SA, TTN and D-Wave on Max-Cut (up to 20,000 nodes), chimera, pegasus, Gset and K2000. The code is released as [mindquantum/algorithm/qaia](https://github.com/mindspore-ai/mindquantum/tree/master/mindquantum/algorithm/qaia). Findings: bSB is best for chimera and small graphs; dSB gives the lowest time-to-target on large graphs. "CAC, CFC, and dSB excel with the highest success probabilities" on large random, skewed and dense graphs, and "given sufficient computational resources and time, CAC and SFC may outperform dSB". CAC and SFC are **hyper-parameter sensitive**, and aSB, SimCIM and NMFA trail. Only **unconstrained** Max-Cut and spin-glass instances were tested.
- Leleu 2021 (CAC) compares against SA and mean-field or chaotic annealing, not SB. Kanao & Goto 2022 (HbSB) compare against dSB only (below).

**What the low-rank literature does and does not give us** `[inference]`:
- **Minimizing** a PSD rank-K quadratic plus a linear term over binaries, which is our E(x), stays NP-hard at K = 1: min (aᵀσ)² is number partitioning. The Allemand/Del Pia polynomial cases cover *maximization* only, so they do not help.
- **An SB/CIM/SimCIM step is matrix-free for free.** Write x = (σ+1)/2. Then J·σ = −½ Dᵀ(α ⊙ (D σ)) up to scaling, and the field is h = Dᵀ(α⊙(C − τ − ½D1)) − ½μs (derivation left to the implementer). Moving the diagonal Σ_w α_w d_{e,w}² into a constant is required because SB assumes diag(J) = 0. Each step costs O(nnz(D)) ≈ 3n per replica. At n = 10^6 with 64 replicas and 10^4 steps that is about 4×10^12 flops: minutes on 24 cores (arithmetic, unbenchmarked). SB's ξ₀ needs ‖J‖_F² = ‖Λ^{1/2}(DDᵀ)Λ^{1/2}‖_F² minus the diagonal term, which is an m×m computation.
- **For single-flip SA/tabu, low rank is irrelevant, because locality already makes flips cheap.** Keep L_w incrementally. Flipping e changes only its 1–3 windows, so ΔE is O(1) for the surrogate, and the *true* max_w L_w (via a max-heap over windows) and the exact knapsack residual are also O(1) to O(log m). A custom local search therefore needs neither the QUBO nor the surrogate. An explicit sparse Q instead costs O(deg_e), about thousands of neighbours per flip.
- **Explicit sparse Q sizing** (for dwave-samplers, MQLib, OpenJij). nnz(Q) ≈ Σ_{w∈A} n_w² (n_w = episodes touching w). At n = 10^5 with all 144 windows, n_w ≈ 1.4k, so about 3×10^8 nnz, roughly 2.5–5 GB in CSR: feasible. At n = 10^6 with all windows it is about 3×10^10 nnz, which is infeasible. Restricting to |A| ≈ 10 active windows gives about 2×10^9 nnz, which is borderline. Python-dict BQMs cost far more per coupler than CSR `[UNVERIFIED overhead]`.

## 6. (a) Ranked shortlist to install and test (CPU-only, our instance shape)

Setup for every arm: build (D, C, s, α, μ) once, peg with LP, then run each arm on the same contested sub-problem, and on the full n where the arm scales. Apply the same greedy repair, and report the true max_w L_w and the gap to z_LP.

1. **MindQuantum QAIA: bSB, dSB, CAC, CFC, SFC, SimCIM on sparse J + h, with a matrix-free patch.**
   `conda create -n qaia python=3.11 && conda activate qaia && pip install mindquantum==0.12.0 scipy`
   - One API gives the complete Zeng et al. comparison set (SB and CIM variants), which covers gaps 1 and 2 in a single install.
   - Start by passing an explicit CSR Q for n ≤ 10^5. Then subclass or monkey-patch: construct with a tiny placeholder of the right shape, pass `xi=` explicitly, and set `solver.J` to an object whose `.dot(X)` returns `Dᵀ(α[:,None]*(D@X))`. That removes the n² barrier `[inference; needs a test]`.
   - Caveats: wheels exist only for Python 3.9–3.11, and the package is large (a quantum simulator). The CPU path is NumPy/SciPy, so it is single-process apart from BLAS threads; use `batch_size` for replicas. There is no heated SB. You must write the μ-bisection and α-reweighting loop yourself.
2. **`qqa` (QQA4CO): feed it (P) as MPS.**
   `pip install torch --index-url https://download.pytorch.org/whl/cpu && pip install qqa==0.11.0 "qqa[highs]"`
   - This is the only candidate that may take the *true* min-max plus knapsack without a surrogate, via MPS, worst-case factors and augmented-Lagrangian constraints.
   - Caveats: v0.x changes weekly, the licence metadata is contradictory (clarify before redistributing), and every capability is a README claim we have not tested. Check `qqa inspect`/`qqa plan` output first.
3. **FEM with `customize`: expected smooth-max load plus budget, matrix-free in torch.**
   `git clone https://github.com/Fanerst/FEM && pip install torch --index-url https://download.pytorch.org/whl/cpu numpy scipy pandas`
   - Write `expected_func(J,p)`: capture torch-sparse D in a closure, compute μ_w = C_w − (D p)_w, and return logsumexp(β μ) plus a budget term. This is O(nnz(D)) per step with autograd.
   - It is evidenced to 10^6 variables on bMinCut. Caveats: no LICENSE file (ask the authors, or keep it internal), research-grade API, and built for GPUs (CPU works but is slower).
4. **Classical QUBO baselines on the explicit sparse Q (the fair "is SB any good?" control).**
   `pip install dwave-samplers dimod`, plus `git clone https://github.com/MQLib/MQLib && make`
   - SA/Tabu/SteepestDescent, and MQLib's Burer2002 and Palubeckis heuristics, with a per-instance time limit.
   - Caveat: explicit Q is feasible only for n ≲ 10^5, or 10^6 after restricting to active windows (§4). In addition, build a **custom O(1)-per-flip SA/tabu on the true objective** in numba. We expect it to dominate every QUBO arm `[inference]`.
5. **(Reference only) `cim-optimizer` and `simulated-bifurcation`, both dense.**
   `pip install cim-optimizer` (then pin torch ≥ 2 yourself and ignore `requirements.txt`), and `pip install simulated-bifurcation==2.0.0`
   - Use them only on the pegged sub-problem with n ≲ 5×10^4, to cross-check that the MindQuantum SB/CAC numbers match the reference implementations. The bqth29 package is the only one with **HbSB/HdSB** (`heated=True`).

Not recommended: PySA (dense), tamc (sparse-graph cluster moves, no licence), APT/NMC (spin-glass research code), all cloud machines (DA, SQBM+, Amplify, VeloxQ, AIM).

## 7. (b) Is "matrix-free SB exploiting low-rank Q with a Lagrangian knapsack" novel?

**Verdict: no prior publication found for the exact combination (confidence about 70%). As an algorithmic idea it would be judged incremental (confidence about 90%).**
- **Already published:** low-rank or multicomponent Ising with a knapsack (Yamashita PRL 2023; Yao & Yu 2026, 102k spins; both SA and slack-penalty). Low-rank-aware Ising dynamics (SPIM literature; Wang et al. 2025). Lagrangian or augmented-Lagrangian inequality handling on Ising solvers (Ohzeki; Takabayashi 2025 on QA; Delacour DATE 2025 on p-bits; Awai 2026 on the SA engine). Sparse-J SB/CAC implementations (MindQuantum). SB with penalty constraints (Toshiba SQBM+).
- **Not found:** SB or CIM dynamics using an **implicit Dᵀ(α⊙D·)** coupling, a **dual-updated budget price μ**, and **IRLS/softmax α-reweighting toward a min-max**, run at n = 10^5–10^6.
- **Where the gap could be missed:** Toshiba SQBM+ internals, Chinese-language SB literature, and 2026 SPIM preprints (the field is active; arXiv 2609.x already has several). A reviewer will see matrix-free SB as the obvious SPIM-emulation trick, so any claim should rest on the *formulation and evaluation*, not on the solver. This is consistent with REPORT.md's framing.

## 8. (c) Evidence that any Ising approach beats LP/MILP on low-rank or partitioning-type constrained problems

**None found for problems like ours.** What exists:
- **EIM vs Gurobi on QKP, n ≤ 300** (Akishima 2025). EIM "obtained optimal solutions for shorter or comparable execution times", but EIM time is measured "until the optimal solution is found" (an oracle stop), while "the execution time of Gurobi is the time required to guarantee optimality". The comparison is not apples to apples, and QKP has a **dense quadratic** objective, unlike ours.
- **Delacour 2025** beats Fujitsu DA on QKP and MKP, not MILP. **Awai 2026** compares only penalty against augmented Lagrangian.
- **FEM bMinCut** beats METIS and matches KaFFPaE, which are heuristics, not MILP.
- **VeloxQ** beats CPLEX on dense unconstrained QUBO families (CPLEX hits 1,000 s at P₁₀ while VeloxQ stays under 1 s). That is dense, unconstrained and cloud-based.
- **Şeker, Tanoumand, Bodur**, *Appl. Soft Comput.* 127 (2022) ([arXiv:2012.12264](https://arxiv.org/abs/2012.12264)): DA "rivals the state of the art, particularly for large instances" on QAP, QCPP and SGCP reformulations. Those are quadratic objectives with assignment-type constraints.
- **SPIM NPP vs Gurobi** (Prabhakar 2023): claimed benchmark, outcome `[UNVERIFIED]`.
- **Against Ising on our structure:** SA loses to Karmarkar–Karp on number partitioning (Johnson et al. 1991). Ohno 2024 (in REPORT) trails Gurobi on QKP. Rathore 2025 load balancing is no better than SA or steepest descent. Kalinin & Berloff (*Commun. Phys.* 5, 20, 2022; [code](https://github.com/kir-kalinin/Complexity-continuum-within-Ising-formulation-of-NP-problems), MIT) show instance hardness for Ising dynamics varies widely, with Gurobi as the exact reference.
- **Bottom line:** with a linear min-max objective, about 1,000 rows and an LP that is nearly integral, the literature gives no reason to expect any Ising arm to beat HiGHS plus rounding. This reinforces REPORT.md's recommendation.
