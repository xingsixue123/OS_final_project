4

PeakBaleen keeps Baleen’s pipeline and changes two places. Offline, on the training day, we replace Baleen’s average-optimal oracle with a min–max QUBO that minimizes the busiest window under the same write budget, and solve it with an Ising solver, parallel tempering. We call its solution our peak-aware oracle: it becomes the training labels for Baleen’s GBM, which also gets a causal load feature. Online, a load meter measures the disk time of the last ten minutes of requests, using only the past. The GBM scores each request, and the admission bar adapts to load: when the system is busy the bar drops, so the write budget is spent where the peak is.
