## Sources

Primary list: the official PVLDB volume index at https://www.vldb.org/pvldb/volumes/16/ . The
rendered page lazy-loads the issue tables, so I fetched the raw HTML with `curl` and parsed the
embedded `__NEXT_DATA__` JSON (`props.pageProps.groupedIssues["13"]`). That array holds 15
entries for Volume 16, Number 13: one "Front Matter" entry (no page range, editors Koutrika and
Yang) plus **14 research papers**, pages 4160-4353. Front Matter is not a paper and is excluded
from the count, giving TOTAL_PAPERS = 14.

Cross-check: OpenAlex API query
`https://api.openalex.org/works?filter=primary_location.source.issn:2150-8097,biblio.volume:16,biblio.issue:13`
returned `count: 14`, and the titles/first pages match the vldb.org list one-for-one
(4160, 4174, 4188, 4202, 4216, 4230, 4240, 4254, 4268, 4282, 4296, 4310, 4324, 4339). OpenAlex
also supplied the DOIs (10.14778/3625054.3625055 ... .3625068, a contiguous block confirming the
issue is complete with no missing entry).

DBLP (`dblp.org/db/journals/pvldb/pvldb16.html` and the DBLP search API) and the ACM DL TOC
(`dl.acm.org/toc/pvldb/2023/16/13`) were both attempted but are behind bot-challenge walls
(Anubis / Cloudflare) and returned no usable data; OpenAlex served as the second source instead.

Per-paper screening used the full PDF text of all 14 papers (downloaded from vldb.org and
converted with `pdftotext`), which let me read every abstract and every "PVLDB Artifact
Availability" statement directly rather than relying on summaries. Repository URLs were then
checked for liveness with HTTP requests and, for GitHub, via the GitHub REST API.
